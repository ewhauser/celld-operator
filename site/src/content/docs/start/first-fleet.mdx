The operator is installed, `fleets/celld-runtime` has access to your dedicated bucket, and the operator has its separate read-only identity. This example creates three Bucket replicas across three real zones in the bucket's region. Use a **new bucket** for this fleet; a reservation stays associated with its fleet UID.

<Steps>

1. **Save the fleet manifest as `my-fleet.yaml`.** Replace the bucket, region and zones with your own values. The listed zones must exist in your cluster and region; at least one eligible node is needed for each replica. The runtime image is omitted so the operator selects its pinned celld v0.5.0 digest.

   ```yaml title="my-fleet.yaml"
   apiVersion: celld.eric.dev/v1alpha1
   kind: CelldFleet
   metadata:
     name: my-fleet
     namespace: fleets
   spec:
     qualification: Experimental
     profile: Bucket
     replicas: 3
     serviceAccountName: celld-runtime
     storage:
       bucket: YOUR_DEDICATED_BUCKET
       region: YOUR_AWS_REGION
       sizeGiB: 10
     placement:
       azCount: 3
       zones: [YOUR_REGION_ZONE_A, YOUR_REGION_ZONE_B, YOUR_REGION_ZONE_C]
       mode: Strict
   ```

2. **Apply it to the explicit context.**

   ```bash
   kubectl --context YOUR_CONTEXT apply -f my-fleet.yaml
   kubectl --context YOUR_CONTEXT -n fleets get celldfleet my-fleet
   ```

3. **Wait for the workload and inspect status.** The Bucket profile creates a Deployment named `my-fleet` and an application Service of the same name on port 8080. The workload should have three ready replicas when all nodes and bucket credentials work.

   ```bash
   kubectl --context YOUR_CONTEXT -n fleets wait celldfleet/my-fleet \
     --for=condition=InfrastructureReady=True --timeout=180s
   kubectl --context YOUR_CONTEXT -n fleets rollout status deployment/my-fleet --timeout=300s
   kubectl --context YOUR_CONTEXT -n fleets get deployment/my-fleet,service/my-fleet
   kubectl --context YOUR_CONTEXT -n fleets get celldfleet my-fleet -o yaml
   ```

</Steps>

Look for `Ready=True`, `Blocked=False`, and `readyReplicas: 3` after reconciliation. `InfrastructureReady=True` only means the Kubernetes objects match; it can be true while Pods are Pending. `ProductionQualified=False` is expected for this experimental release. [Verify and observe](../verify/) explains those signals and where to look if they do not appear.

The application Service is internal. Only client Pods in `fleets` labeled `celld.eric.dev/client-of: my-fleet` can reach it through the generated NetworkPolicy. Port 8081 is private to peers and the operator. For a retained-disk setup, read [PersistentFleet profile](../../concepts/profiles/) before creating it; it needs EBS CSI, a retained StorageClass and a digest-pinned launcher image.
