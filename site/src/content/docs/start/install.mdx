There is one operator installation per cluster. It watches every namespace that holds fleets but can only act inside namespaces where you grant it the fleet Role. Read the [installation and operations contract](../../contracts/operations/) for the full text; this page is the ordered walk-through.

:::caution[Use an explicit kubeconfig context]
The operator never infers a default cluster, and neither should you. Every command below takes `--context`. Never enable `--local-test` on EKS; it selects local MinIO and synthetic credentials for the disposable integration harness.
:::

## Prerequisites you provide

| Requirement | Why |
| --- | --- |
| Kubernetes 1.31 or newer with IPv4 Pod networking | Prototype target; the chart accepts 1.30+ but the API contract names 1.31. |
| A CNI that enforces NetworkPolicy, independently verified | The generated policies isolate celld's private peer and launcher ports. The operator cannot verify enforcement itself. |
| One dedicated S3 bucket per fleet, no external writers, no object expiry | The whole bucket is reserved for the fleet. Evidence records must not expire. |
| A ServiceAccount in each fleet namespace bound to a runtime IAM role (EKS Pod Identity or IRSA) | The runtime's credentials. The CR stores no secrets. |
| A separate read-only AWS identity for the operator's `nodes/` and `log/` evidence reads | Contraction evidence. The operator writes nothing to S3. |
| For PersistentFleet: EBS CSI, a StorageClass with `ebs.csi.aws.com`, `reclaimPolicy: Retain`, `volumeBindingMode: WaitForFirstConsumer` | Retained volumes are recovery assets. Delete reclaim would destroy them. |
| Node capacity in every zone you list | Strict placement leaves Pods Pending rather than relaxing zones. |
| Optional: Metrics Server, Prometheus Operator CRDs | Capacity policy needs Metrics Server. Prometheus is never a prerequisite. |

## Install with Helm

<Steps>

1. **Build or pull an image.** Nothing is published yet; the development manifest references an unpublished `:dev` tag. Build and push your own, then record its digest.

   ```bash
   make image VERSION=dev
   ```

2. **Apply the CRDs explicitly.** Helm installs CRDs once and never upgrades or removes them, so the repository treats them as a separate step on install and on every upgrade.

   ```bash
   kubectl --context YOUR_CONTEXT apply -f config/crd/
   ```

3. **Install the chart**, listing every namespace that will hold fleets so the chart renders the namespaced Role and RoleBinding into each.

   ```bash
   helm --kube-context YOUR_CONTEXT upgrade --install celld charts/celld-operator \
     --namespace celld-system --create-namespace \
     --set image.repository=YOUR_REGISTRY/celld-operator \
     --set image.digest=sha256:YOUR_DIGEST \
     --set 'fleetNamespaces={fleets}'
   ```

   For PersistentFleet also set `launcherImage` to the same digest-pinned image; the launcher binary ships inside it. See the [chart values reference](../../api/helm-values/).

4. **Grant the fleet Role by hand** for any namespace you did not list. A fleet in a namespace without it reports `NamespaceAccessDenied` and nothing is created there.

   ```bash
   kubectl --context YOUR_CONTEXT -n fleets apply -f config/rbac/fleet-namespace.yaml
   ```

5. **Attest NetworkPolicy enforcement only after verifying it.** `networkPolicyEnforced=true` is an administrator assertion, not a CNI installer. Provisioning is blocked until it is set.

   ```bash
   helm --kube-context YOUR_CONTEXT upgrade celld charts/celld-operator \
     --namespace celld-system --reuse-values --set networkPolicyEnforced=true
   ```

</Steps>

## Install with plain manifests

The same steps without Helm, using the development manifest:

```bash
kubectl --context YOUR_CONTEXT apply -f config/crd/
kubectl --context YOUR_CONTEXT apply -f config/manager/operator.yaml
kubectl --context YOUR_CONTEXT -n YOUR_FLEET_NAMESPACE apply -f config/rbac/fleet-namespace.yaml
```

Edit the Deployment's `args` to add `--network-policy-enforced` after verification, and `--launcher-image` for PersistentFleet. Every flag is listed in the [operator flags reference](../../api/operator-flags/).

## Upgrading the operator

Before upgrading, back up together: fleet specifications, `CelldStorageReservation` objects, the immutable journal archive ConfigMaps in each fleet namespace, and launcher credential Secrets. Inspect CRD changes and apply `config/crd/` explicitly. Never roll back to a controller that cannot read the persisted journal version; the current version and compatibility rules are in [journal archives](../../contracts/journal-archives/).
