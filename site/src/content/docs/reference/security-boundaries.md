title: Security boundaries
description: What the operator can touch, which network paths are private, what it trusts, and which credentials it never holds.

The operator needs Kubernetes write access to coordinate a fleet, but it has a narrower AWS role than the celld runtime. The generated NetworkPolicy limits fleet traffic only when your CNI enforces it. These are the boundaries to verify before provisioning.

## Kubernetes permissions

The ClusterRole is deliberately small. Everything the operator does inside a fleet namespace is granted per namespace through `config/rbac/fleet-namespace.yaml`, and a fleet in a namespace without that Role is reported as `NamespaceAccessDenied` rather than reconciled.

| Scope | Resources | Verbs |
| --- | --- | --- |
| Cluster | `celldfleets` | get, list, watch, patch |
| Cluster | `celldfleets/status` | get, patch |
| Cluster | `celldstoragereservations` | get, create, update |
| Cluster | `persistentvolumes`, `storageclasses` | get |
| Cluster | `nodes` | get, patch |
| Cluster | `volumeattachments` | list |
| Operator namespace | `leases` | get, list, watch, create, update, patch |
| Operator namespace | `events` | create, patch |
| Each fleet namespace | `serviceaccounts` | get |
| Each fleet namespace | `services`, `persistentvolumeclaims`, `secrets`, `configmaps`, `networkpolicies`, `poddisruptionbudgets` | get, create |
| Each fleet namespace | `pods` | get, list, update, delete |
| Each fleet namespace | `deployments`, `statefulsets` | get, create, update, delete |
| Each fleet namespace | `replicasets`, `metrics.k8s.io` `pods` | get |
| Each fleet namespace | `events.k8s.io` `events` | create, patch |

Notable absences: no cluster-wide delete, no Secret list, watch or delete, no PVC delete, no PV write, and no permission on the runtime's ServiceAccount tokens. Runtime service accounts receive no Kubernetes API token at all. The chart and the manifests are kept in parity by `make chart-check`. Source: [operations](../../contracts/operations/), [PersistentFleet lifecycle](../../contracts/persistent-fleet-lifecycle/).

## Network paths

| Port | Who may reach it | Enforced by |
| --- | --- | --- |
| 8080 application | Pods in the fleet namespace labelled `celld.example.com/client-of: <fleet>` | Generated NetworkPolicy |
| 8081 celld internal | Same-fleet peers and operator-namespace Pods labelled `app.kubernetes.io/name: celld-operator` | Generated NetworkPolicy |
| 8083 launcher | Operator-namespace Pods only; no Service exposes it | Generated NetworkPolicy plus HMAC on every request and response |
| 8082 operator health, 8084 operator metrics | Cluster-internal; restrict with your own policy | Your network policy |

The NetworkPolicy objects are generated, but the operator cannot verify that the CNI enforces them. `--network-policy-enforced` is an administrator attestation and provisioning is blocked without it. Public ingress, TLS and DNS are outside the operator. Source: [ADR 0009](../../decisions/0009-service-and-ingress-boundary/), [fleet API](../../contracts/fleet-api/).

## Credentials and identities

| Identity | Held by | Purpose |
| --- | --- | --- |
| Runtime IAM role | The fleet's ServiceAccount, via EKS Pod Identity or IRSA, provisioned by you | celld's bucket access. Never stored in the CR. |
| Evidence reader | The operator's ServiceAccount, separate and read-only | `nodes/` and `log/` listing plus bounded reads of `nodes/*.json`. No S3 writes, no application data reads, no bundle-body reads. |
| EC2 fencing | The operator's normal workload credentials, only when both fencing flags are set | `TerminateInstances` and `DescribeInstances` on tagged dedicated instances in one account and region. |
| Launcher key | Immutable per-fleet Secret created exclusively by the operator, 32 random bytes | Domain-separated HMAC on launcher requests and responses. Its digest is journaled; uncertain adoption fails. |
| Lease generation seed | Ed25519 seed generated by the launcher and consumed by celld at boot | Lets the operator know the node's lease generation independently of HTTP. |

The operator writes no S3 metadata and creates no AWS resources. Source: [ADR 0008](../../decisions/0008-recovery-evidence-and-conservative-removal/), [S3 recovery evidence](../../history/s3-recovery-evidence/), [EC2 fencing](../../contracts/infrastructure-fencing/).

## Trust assumptions

The safety argument for PersistentFleet retirement depends on these. Each is a version-specific assumption about the pinned release, not a general property.

- The pinned launcher, celld binary and their native subprocesses do not close or unlink the inherited lock descriptor while retaining disk access.
- Workloads cannot compromise those native processes or read or forge the launcher credential.
- Namespace and storage administrators do not rewrite journal authority or bypass attachment fencing with force detach.
- A local file lock does not fence a different kernel, an unsafe EBS force-detach or a copied filesystem. Those events are outside the supported path.
- The S3 bucket has exactly one fleet as writer and no lifecycle rule that expires evidence.

Source: [PersistentFleet lifecycle](../../contracts/persistent-fleet-lifecycle/), [shared lifecycle safety](../../history/shared-lifecycle-safety/).

## Supply chain

- Runtime images are pinned to exact release index digests; tags are rejected. See [compatibility](../compatibility/).
- The operator image is a static Go binary on a nonroot distroless base; the launcher is injected by an init container without modifying the celld image.
- Release publication refuses to overwrite an existing version, records the image digest in the chart, and verifies the chart pulled back from the registry. Nothing has been published yet.
- GitHub Actions in this repository are pinned by commit SHA.

Source: [operations](../../contracts/operations/#releases).

## Things the operator will not do for you

- Delete or free a reservation, retained PVC or archive page.
- Remove its own deletion finalizer before the journaled RetainData shutdown reaches Cleanup. After proving the shutdown, it removes the finalizer while retaining the reservation, journal, PVCs and credentials. See [deletion](../../operate/deletion/).
- Adopt a pre-existing PVC, even with matching labels.
- Repair drifted templates disruptively.
- Bypass a gate on a timeout, annotation or flag.
