# celld runtime qualification for a Kubernetes fleet operator

18 September 2026. This is a source and bounded local-policy assessment of the [fleet operator design](/Users/ewhauser/Downloads/Celld_Fleet_Operator_Design.docx), especially sections 2, 5, 9–11, and 15. It is **not** an EKS, S3, EBS, or end-to-end durability qualification. No upstream source or cloud resource was changed.

## Decision

Follow-up: the user subsequently accepted read-only S3 metadata access. See [the proposed S3 evidence contract](s3-recovery-evidence.md). That review also found that recovery can publish a loss declaration and then seal a log; a seal alone must not be described as lossless recovery. The HTTP-only conclusions below still apply, but are not a rejection of a qualified S3 metadata adapter.

Use **celld v0.5.0** as the candidate unmodified baseline, pinned to commit [`12d5b6333fe52717325addcfe1e99e9fd4f77bcd`](https://github.com/denoland/celld/tree/12d5b6333fe52717325addcfe1e99e9fd4f77bcd) and multi-architecture image `ghcr.io/denoland/celld@sha256:df8e74bb9a059df5779644368984933eba76acd6a2d196672732f4368f760fc8`. The [GitHub release](https://github.com/denoland/celld/releases/tag/v0.5.0) is published; the digest was resolved from both the `v0.5.0` and immutable `sha-12d5b6333fe52717325addcfe1e99e9fd4f77bcd` image tags. The remote `main` HEAD equals this tag at review time; the conclusions below apply to this release, not future `main`. The design's sample image value is a placeholder, not a qualified pin.

**Go for an operator prototype and Bucket-profile qualification. No-go for promising production automatic scale-in in either profile yet.** PersistentFleet automatic scale-in has a specific interface blocker: the release does not expose a machine-readable fleet-wide proof that a removed node's open log has been recovered and its retained follower fragments are no longer needed. Keep its EBS PVCs and block further contraction. Bucket-profile scaling still needs live failure and load tests, especially the startup gate under pressure. A controller that only sees Kubernetes and the released HTTP API cannot independently establish S3 health or the peer-log recovery proof.

## PersistentFleet disk and failure boundary

The operator may remove **compute while retaining its EBS volume** as a reversible maintenance action if it preserves the PVC, allows SIGTERM's handoff, and stops when completion is uncertain. This is not proof that the remaining fleet can safely lose another node: acknowledged writes may still exist only in retained follower logs, and the [runtime recovery path](https://github.com/denoland/celld/blob/12d5b6333fe52717325addcfe1e99e9fd4f77bcd/crates/celld/node_log.rs#L4291-L4304) requires a complete sealed witness before folding them to S3. A cold read gates on this for its particular predecessor; it does not inventory every dormant cell for the operator. Retaining the PVC preserves a recovery option, provided the disk remains accessible. Without a released recovery certificate or equivalent authoritative API, the automatic profile must halt after an uncertain removal, preserve all claims, and require a documented human recovery procedure before further contraction. An operator-only scan of celld's bucket records would duplicate recovery interpretation and violate the no-S3-access boundary.

For a StatefulSet ordinal, keep `CELLD_NODE` stable and unique for that logical node, mount the **same** retained PVC at `CELLD_WATCH`, and keep its advertised peer address reachable on restart. The default node ID is random each process start, while follower fragments live under `CELLD_WATCH/peerlog/<node>/<generation>/`; predecessor recovery runs before replacing the log record and serves authenticated follower tails during recovery. A new pod using the old identity with an empty or wrong disk is unsafe to treat as a normal retained-disk restart. [Identity/work directory](https://github.com/denoland/celld/blob/12d5b6333fe52717325addcfe1e99e9fd4f77bcd/crates/celld/main.rs#L3724-L3761), [follower layout](https://github.com/denoland/celld/blob/12d5b6333fe52717325addcfe1e99e9fd4f77bcd/crates/celld/node_log.rs#L1089-L1124), [startup ordering](https://github.com/denoland/celld/blob/12d5b6333fe52717325addcfe1e99e9fd4f77bcd/crates/celld/main.rs#L4255-L4301).

The [supervisor requirement](https://github.com/denoland/celld/blob/12d5b6333fe52717325addcfe1e99e9fd4f77bcd/docs/guarantees.md#L101-L113) is unlimited restarts **at least one lease lifetime apart** (`CELLD_TTL_MS` defaults to 10 seconds). Kubernetes may restart a first failure immediately; its later crash backoff is not a proof of this minimum ([Kubernetes pod lifecycle](https://kubernetes.io/docs/concepts/workloads/pods/pod-lifecycle/)). Qualify a signal-forwarding launcher or another supervisor mechanism that delays each restart by a full TTL even when prior exit time is unknown, persists any needed timestamp across container and pod restarts, and test self-fence, SIGKILL, and node loss. Do not use a liveness probe whose failure restarts a sound but pressured or storage-waiting process.

Set StatefulSet `persistentVolumeClaimRetentionPolicy.whenScaled=Retain` and `whenDeleted=Retain` and verify reclaim policy and finalizers in the actual cluster ([Kubernetes StatefulSet API](https://kubernetes.io/docs/reference/kubernetes-api/apps/stateful-set-v1/)). Validate the requested AZ count and available capacity; default to strict node and zone spread, with an explicit per-fleet relaxation. An EBS volume can attach only to a node in its own AZ ([AWS EBS](https://docs.aws.amazon.com/ebs/latest/userguide/ebs-attaching-volume.html)); a strict AZ spread rule may leave the ordinal Pending if no capacity exists there. Relaxing **pod** spread must never silently create a fresh disk for an existing logical identity. No released celld surface guarantees **runtime follower** diversity across AZs; therefore an arbitrary AZ-loss RPO=0 promise for fleet acknowledgements is unavailable without runtime placement support or a separately qualified failure model. EBS itself is replicated within one AZ, not across AZs ([AWS EBS features](https://docs.aws.amazon.com/ebs/latest/userguide/EBSFeatures.html)).

## Source check and next gates

The only local experiment compiled the unmodified v0.5.0 `celld-logic` dependency in an external scratch project and called its released `drain::fleet_status` function. With one pressured incumbent and a new empty paced-handoff node, `joining_contributes_successor_capacity=true` but readiness returned `MemoryHeadroom { node: "old" }`; after clearing pressure it returned `Ok(())`. This verifies the policy branch, **not** pod startup, service routing, or EKS behavior. `cargo test -p celld-logic` compiled but selected zero tests. No AWS qualification was performed.

1. Run the pinned image on EKS with externally provisioned S3, EBS, IAM/Pod Identity, and at least the configured AZ count. Verify anonymous image pull, startup storage probes, direct pod peer routing, NetworkPolicy isolation, Metrics Server coverage, and the first-restart lease delay. Record architecture-specific image digest, peer protocol, storage format, and observed `/state` JSON.
2. Under sustained incumbent `pressured=true` and `capacity_waiting>0`, add nodes. Measure health 503 duration, public routing, new-cell placement, idle-cell rebalance, and whether useful capacity appears **without** setting `CELLD_READY_FLEET_GATE_MS=0`. If it does not, block pressure-triggered automatic scale-out claims and seek an upstream runtime fix or a documented, tested configuration.
3. With a client ledger of acknowledged operation IDs, interrupt WebSockets and ambiguous HTTP/RPC calls during single and correlated pod/node loss, SIGKILL, S3 outage, and EBS detach/reattach. Verify application reconnect and stable retry IDs; the runtime expressly does not replay ambiguous work ([handoff contract](https://github.com/denoland/celld/blob/12d5b6333fe52717325addcfe1e99e9fd4f77bcd/docs/README.md#L730-L747)). Measure recovery and stop bounds. Test each durability profile separately.
4. For PersistentFleet, demand a released machine-readable log-session recovery/retention contract before enabling repeatable automatic scale-in under no-operator-S3 access. Test an idle cell whose last acknowledged write is absent from S3, then remove a follower, retain its PVC, attempt a second removal, and verify that the controller blocks until authoritative recovery completion. Test restored identity on the original AZ disk and the missing-AZ case.
5. Qualify every image transition against a versioned peer/storage compatibility matrix. For v0.4.1→v0.5.0, execute the documented stopped-fleet procedure, including lease expiry, retained disks, and prevention of old writers; do not model it as a rolling StatefulSet update ([migration procedure](https://github.com/denoland/celld/blob/12d5b6333fe52717325addcfe1e99e9fd4f77bcd/docs/guarantees.md#L359-L400)).
